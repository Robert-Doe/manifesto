Module 04 Demo — Tab API, Alarms & Browser APIs

⚡ Browser API Survey Test Page

This page verifies all the new capabilities added in Module 04: service worker alarms, the Tab Manager page, optional permissions for tabs / bookmarks / history / notifications, and the background message relay.

Background Service Worker

  • ✓Open chrome://extensions → find NeuralTab → click "Service worker" link. The service worker DevTools panel opens. In the Console tab, you should see no errors on load.
  • ✓In the service worker console, type: chrome.alarms.getAll(console.log). You should see an array containing one alarm named "tab-analysis" with periodInMinutes: 30.
  • ○In service worker console, type: chrome.runtime.sendMessage({action:'triggerTabAnalysis'}). Then check chrome.storage.local.get(['lastTabAnalysis'], console.log) — the timestamp should have just updated.

Tab Manager Page

  • ✓Click the NeuralTab toolbar icon → popup opens → click "Open Tab Manager". The Tab Manager page opens in a new tab at chrome-extension://…/tab_manager.html.
  • ○If the tabs permission is not granted, you see the purple permission banner at the top. Click "Grant permission" and accept the Chrome dialog. The banner disappears and your tabs load grouped by domain.
  • ○Click "Switch" on any tab — that tab becomes active. Click "✕" on a tab — it closes without affecting other tabs.
  • ○If bookmarks permission is granted: click "★ Save" on a tab. Open your bookmarks (Ctrl+Shift+O) and look for a "NeuralTab Saves" folder — the tab should be there.
  • ○If history permission is granted: type a search term in the History panel sidebar → click Go. Results appear as clickable items that open new tabs.
  • ○Click "Group by domain" — Chrome groups tabs with matching domains. Look at the tab bar — groups appear with coloured labels.

Settings → Tabs & Alarms

  • ✓Right-click toolbar icon → Options → "Tabs & Alarms" section. The alarm status box shows "Next run: [time] · Period: 30 min".
  • ○Click "Run analysis now". The alarm status refreshes. Open the service worker console and type chrome.storage.local.get(['_totalTabCount','_idleTabCount'], console.log) to see counts.
  • ○Toggle "Tab analysis" OFF. Reload the extension. Check alarms — the alarm should still exist (it was created on install, not based on the setting; the setting is checked at alarm fire time). This is intentional — the alarm itself is cheap. The analysis work is gated by the setting.

Permissions → All Four Cards

  • ✓Right-click toolbar icon → Options → "Permissions". All four permission cards are visible: tabs, bookmarks, history, notifications.
  • ○Grant "tabs" permission. The Grant button disappears, a green "✓ Granted" status appears, and a Revoke button appears.
  • ○Click Revoke. The permission is removed and the Grant button reappears. Open the Tab Manager — the banner is back.
  • ○Grant "notifications" permission. Then use the service worker console to send chrome.runtime.sendMessage({action:'triggerTabAnalysis'}) after opening 5+ background tabs. If idle tabs ≥ 5, a desktop notification fires.

Long article — word count and highlight testing

The chrome.tabs API exposes a permission model that surprises most developers the first time they encounter it. You can call chrome.tabs.query() without any permission, but the returned Tab objects have their url and title fields redacted to empty strings. You can count tabs, you can read their IDs and window IDs, but you cannot see what page is loaded in each tab. Granting the "tabs" optional permission fills in those fields. This design reflects Chrome's principle of data minimisation: the API surface remains consistent, but the data it exposes scales with the trust the user has explicitly granted.

The alarm system in Chrome extensions is one of the most important but least understood APIs. A service worker has a hard idle timeout of roughly five minutes — if no events fire for five minutes, Chrome terminates the service worker process to save memory. Any in-flight operations are abandoned. Any state stored in JavaScript variables is lost. The only way to schedule work that runs reliably after the service worker has been killed is chrome.alarms. When an alarm fires, Chrome wakes the service worker specifically to handle the alarm event, runs the onAlarm handler to completion, and then allows the worker to idle out again. This wake-and-terminate cycle is more efficient than keeping the service worker alive continuously.

The chrome.bookmarks API exposes the full bookmark tree as a hierarchical structure of BookmarkTreeNode objects. Each node is either a bookmark (has a url field) or a folder (has a children array and no url). The root nodes are special: Chrome's bookmark bar, "Other Bookmarks", and "Mobile Bookmarks" are the three permanent top-level folders, and their IDs are always "1", "2", and "3" respectively. When NeuralTab creates a "NeuralTab Saves" folder, it uses chrome.bookmarks.create({ title: 'NeuralTab Saves' }) without specifying a parentId, which places it in "Other Bookmarks" by default. This is correct UX — users expect new folders to appear in Other Bookmarks, not cluttering the bookmark bar.

The Tab Groups API (chrome.tabs.group() and chrome.tabGroups.update()) requires no additional permission beyond what chrome.tabs.query() already provides. It was introduced in Chrome 89 and provides a programmatic interface to the same grouping feature users access by right-clicking a tab. Groups can be given a name and a colour from a fixed palette of eight predefined colours. NeuralTab's "Group by domain" feature uses the API to batch-group tabs that share a domain, creating a visual workspace organisation that would take a user minutes to do manually.
