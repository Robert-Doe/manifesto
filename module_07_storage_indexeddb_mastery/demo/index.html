Module 07 — Storage Mastery

Four storage mechanisms, each with distinct constraints, performance characteristics, and correct use cases.

The Four Storage Types at a Glance

chrome.storage.local
5 MB
Default quota (unlimited with flag)

Per-device. Never synced. Survives browser restart. Fastest for frequent writes. NeuralTab stores all operational state here.

chrome.storage.sync
100 KB
Total / 8 KB per item / 1800 writes/hr

Synced across Chrome profiles via Google account. Small, infrequent writes only. Use for user preferences.

chrome.storage.session
10 MB
Ephemeral — clears on browser restart

MV3 only (Chrome 102+). Perfect for transient UI state, per-session tokens, or SW↔page communication that must not persist.

IndexedDB
Unlimited*
With unlimitedStorage permission

Structured, indexed, queryable. Handles millions of rows. NeuralTab uses it for the 10,000-visit page history with full-text search.

IndexedDB Structure

Database: neuraltab-history  (version 1)
└── Object Store: page_visits  (keyPath: "id", autoIncrement: true)
    ├── Index: url       → find all visits to a given URL
    ├── Index: timestamp → range queries, reverse-order cursor (newest first)
    └── Index: domain    → group/filter by domain

Record shape:
{
  id:        1234,        // autoincrement primary key
  url:       "https://example.com/article",
  title:     "Example Article",
  domain:    "example.com",
  wordCount: 847,
  timestamp: 1704067200000
}

The 10,000-Entry Cap — Eviction Logic

async function addVisit(visit) {
  const store = await tx(STORE_VISITS, 'readwrite');
  const count = await idbReq(store.count());
  if (count >= MAX_VISITS) {
    // Open cursor at lowest key (oldest insert) — O(log n)
    const cursor = await idbReq(store.openCursor());
    if (cursor) await idbReq(cursor.delete());
  }
  return idbReq(store.add(visit));  // new entry
}

No full table scan. The autoincrement primary key is itself an ordered index. The cursor opens at the minimum key — the oldest entry — in O(log n) time.
