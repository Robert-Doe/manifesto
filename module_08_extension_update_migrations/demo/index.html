Module 08 — Update Mechanics

Every install, update, and Chrome restart fires different lifecycle events. Getting these right means your users never see a blank screen or corrupt state after an upgrade.

The onInstalled Lifecycle

User installs
onInstalled fires
reason = 'install'. previousVersion = undefined.
→
MigrationManager

All migrations 0.2.0 → 0.8.0 run in version order.
→

User updates 0.6 → 0.8
onInstalled fires
reason = 'update'. previousVersion = '0.6.0'.
→
MigrationManager
run('0.6.0', '0.8.0')
Only migrations 0.7.0 and 0.8.0 run. 0.2–0.6 already applied.
→
Storage upgraded
New keys added
Existing data untouched. New defaults added for new keys.

Three Reasons, Three Behaviors

'install'
Fresh install. Run all migrations from null. Set swStartCount = 1. Open IDB eagerly.
'update'
User upgraded. Increment swStartCount. Run only migrations between previousVersion and currentVersion.
'chrome_update'
Chrome updated but extension version unchanged. Log the event. Do nothing to storage — schema has not changed.

Migration Runner Logic

const MIGRATIONS = {
  '0.7.0': async (storage) => {
    // Only set defaults if keys are missing — idempotency guarantee
    if (!storage.historyVisitCount)
      await StorageManager.set({ historyVisitCount: 0, historyEnabled: true });
  },
  '0.8.0': async (storage) => {
    if (!storage.migrationLog)
      await StorageManager.set({ migrationLog: [], schemaVersion: '0.8.0' });
  }
};

async function run(previousVersion, currentVersion) {
  const sortedVersions = Object.keys(MIGRATIONS).sort(compareVersions);
  for (const target of sortedVersions) {
    const shouldRun = (!previousVersion || compare(previousVersion, target) < 0)
                   && compare(target, currentVersion) <= 0
                   && !log.some(e => e.version === target && e.success);
    if (shouldRun) await MIGRATIONS[target](storage);
  }
}

Key invariant: each migration checks whether its keys already exist before writing. This makes every migration idempotent — safe to run twice without doubling data or overwriting user preferences.
