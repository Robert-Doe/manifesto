MV2 webRequest vs MV3 declarativeNetRequest

MV2: chrome.webRequest (blocking)
  • JavaScript runs for every matching request
  • Service worker must be alive
  • Can inspect request body, headers, URL dynamically
  • Can return modified request from JS logic
  • Slower: IPC + JS evaluation per request
  • Removed in MV3 (blocking mode)
MV3: declarativeNetRequest
  • Rules evaluated in C++ networking engine
  • No service worker needed at intercept time
  • Rules declared statically in JSON
  • No access to request body
  • Much faster: no IPC, no JS
  • Required for request blocking in MV3

DNR Rule Anatomy

{
  "id": 1,               // unique integer per ruleset
  "priority": 1,         // higher wins when multiple rules match
  "action": {
    "type": "block"      // block | redirect | modifyHeaders | allow | allowAllRequests
  },
  "condition": {
    "urlFilter": "||doubleclick.net^",  // uBlock-style URL pattern
    "resourceTypes": ["script", "image"] // filter by resource type
  }
}

The || prefix means "match at start of domain". ^ means separator (end of domain component). These are uBlock Origin filter syntax, adopted by the DNR spec.

webNavigation — Still Available for Observation

// webNavigation is observation-only in MV3 — no blocking
chrome.webNavigation.onBeforeNavigate.addListener(details => {
  if (details.frameId === 0) {  // main frame only
    logNetworkEvent('beforenavigate', details.url);
  }
});

NeuralTab's Network Monitor uses webNavigation to build a live event log. Every main-frame navigation appears in the UI within milliseconds via storage.onChanged (Pattern 4 from Module 06).
