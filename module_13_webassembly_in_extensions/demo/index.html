Module 13 — WebAssembly in Extensions

Binary performance inside the extension sandbox — no unsafe-eval required.

Why Wasm Works in MV3

WebAssembly.instantiate(buffer) compiles a binary buffer, not JavaScript source text. MV3's CSP blocks dynamic code generation from strings (eval, new Function), but binary compilation is explicitly permitted by the CSP spec. This is why you can ship a .wasm file and compile it at runtime without any CSP relaxation.

The Inline Binary Pattern

wasm_runner.js embeds a hand-crafted Wasm fibonacci binary as a Uint8Array literal. This is useful for tiny Wasm modules (<1KB) where shipping a separate file adds overhead. For larger modules, ship a .wasm file in web_accessible_resources and load it via fetch(chrome.runtime.getURL('module.wasm')).

Real Use Cases

Fibonacci is a benchmark subject. Real Wasm value comes from running native C/C++/Rust code in the browser sandbox — things that would be 10-100× slower in pure JavaScript.
