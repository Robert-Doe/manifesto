Module 15 — CDP Part 2: Network & Tracing

Intercept network traffic, read response bodies, and capture performance traces — all via chrome.debugger.

Network Domain Events

After calling Network.enable, CDP fires requestWillBeSent, responseReceived, and loadingFinished events for every request the tab makes. These arrive in chrome.debugger.onEvent in the background service worker. NeuralTab relays them to the cdp_network.html page via chrome.runtime.sendMessage.

Reading Response Bodies

// After Network.responseReceived, fetch the body:
const { body, base64Encoded } = await chrome.debugger.sendCommand(
  { tabId }, 'Network.getResponseBody', { requestId }
);
// body is the raw response text (or base64 for binary)

Performance Tracing

CDP's Tracing domain produces the same data as a Chrome DevTools Performance recording. The trace is streamed as Tracing.dataCollected events (each containing an array of trace events) followed by Tracing.tracingComplete. Collected chunks must be assembled into a complete trace array and can then be loaded into chrome://tracing or Perfetto.

Screenshots

Page.captureScreenshot returns a base64-encoded JPEG or PNG of the full page, not just the viewport. Unlike chrome.tabs.captureVisibleTab, it can capture: full-page height, specific clip rectangles, at specific device scale factors. Requires the debugger to be attached.
