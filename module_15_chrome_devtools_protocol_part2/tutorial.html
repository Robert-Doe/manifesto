The Network Domain

After calling Network.enable, CDP emits an event for every network request the tab makes — before it's sent, when headers arrive, when the body arrives, when it finishes, when it fails. This gives you a complete picture of a page's network activity, including requests that happen during page load before the user sees anything.

// Enable network tracking
await chrome.debugger.sendCommand({ tabId }, 'Network.enable');

// Now you'll receive these events via chrome.debugger.onEvent:
// Network.requestWillBeSent  — request about to be sent
// Network.responseReceived   — response headers arrived
// Network.loadingFinished    — body completely loaded
// Network.loadingFailed      — request failed

chrome.debugger.onEvent.addListener((source, method, params) => {
  if (method === 'Network.requestWillBeSent') {
    console.log(params.requestId, params.request.method, params.request.url);
  }
});

Reading Response Bodies

Response bodies are NOT included in the events automatically — that would be enormous memory usage. To read a body, you call Network.getResponseBody after the loadingFinished event, using the requestId from the events. Chrome only holds the body in memory briefly, so you must request it quickly.

chrome.debugger.onEvent.addListener(async (source, method, params) => {
  if (method === 'Network.loadingFinished') {
    const { body, base64Encoded } = await chrome.debugger.sendCommand(
      { tabId: source.tabId },
      'Network.getResponseBody',
      { requestId: params.requestId }
    );
    // body is text (or base64 if binary)
    const text = base64Encoded ? atob(body) : body;
    console.log('Response body length:', text.length);
  }
});

Performance Tracing

CDP's Tracing domain captures a performance timeline — the same data that appears in the DevTools Performance panel. The trace records every browser event: layout, paint, JavaScript execution, garbage collection, network activity. The data format is the same as Chrome's about:tracing and can be loaded into Perfetto.

// Start tracing
await debuggerSend('Tracing.start', {
  categories: '-*,devtools.timeline,blink.user_timing,v8',
  options: 'sampling-frequency=10000'
});

// Do some work, navigate, etc.

// Stop tracing — data arrives as events, not in response
await debuggerSend('Tracing.end');

// Collect data from events:
const traceEvents = [];
chrome.debugger.onEvent.addListener((src, method, params) => {
  if (method === 'Tracing.dataCollected') {
    traceEvents.push(...params.value);
  }
  if (method === 'Tracing.tracingComplete') {
    // traceEvents is now the full trace
    const traceJson = JSON.stringify({ traceEvents });
    // Load into chrome://tracing or Perfetto
  }
});

Screenshots via CDP

Page.captureScreenshot is more powerful than chrome.tabs.captureVisibleTab: it captures the full page, supports clipping to specific coordinates, can scale to any DPI, and supports both JPEG and PNG. The result is base64-encoded.

const { data } = await debuggerSend('Page.captureScreenshot', {
  format: 'jpeg',
  quality: 80,
  clip: { x: 0, y: 0, width: 800, height: 600, scale: 1 },
  fromSurface: true   // capture full composited page
});
// data is base64-encoded JPEG
const url = 'data:image/jpeg;base64,' + data;
document.getElementById('preview').src = url;
Architecture Note

CDP events fire in the service worker via chrome.debugger.onEvent. To display them in the cdp_network.html page, relay them via chrome.runtime.sendMessage. The page listens via chrome.runtime.onMessage. This is the standard SW → page communication bridge from Module 06.

Exercise 15-A — Request Filter

Add a filter to cdp_network.html that shows only XHR/fetch requests (resourceType === 'XHR' or 'Fetch'). Navigate a modern SPA page with the network panel open and observe the API calls the page makes — the kind of data visible only via CDP, not via webNavigation.

Exercise 15-B — Largest Content Paint

Use the Performance domain to capture the LargestContentfulPaint metric. After Performance.enable, navigate to a page and then call Performance.getMetrics. Find and display the LCP value. Compare it against Core Web Vitals thresholds: good (<2.5s), needs improvement (2.5-4s), poor (>4s).

Exercise 15-C — Full-Page Screenshot Tool

Build a "screenshot" button in the popup.html that: (1) attaches the debugger to the active tab, (2) calls Page.captureScreenshot, (3) detaches the debugger, (4) opens a new tab with the image as a data URL. Handle the case where the debugger is already attached. Add a download button on the screenshot tab.
