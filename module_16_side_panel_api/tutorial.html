Module 16 — Side Panel API

NeuralTab Curriculum · Module 16 of 25

The Persistence Problem Popups Can't Solve

The popup closes the moment the user clicks anywhere outside it. This makes popups ideal for quick actions — check a value, trigger a function, change a setting — but completely unsuitable for features that need to observe or react to ongoing browsing. Research assistants, reading modes, history trackers, live analytics: all of these need to stay open while the user browses. That's what the side panel exists for.

Setup: Two Lines in onInstalled

// In background.js onInstalled:
await chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
// Now the extension icon opens the side panel instead of the popup.

// Or open programmatically:
chrome.contextMenus.onClicked.addListener((info, tab) => {
  chrome.sidePanel.open({ windowId: tab.windowId });
});

The Panel's Lifecycle

The side panel page is a full extension page — it has access to all chrome.* APIs, loads CSS and JS, and can run indefinitely while it's visible. Unlike the popup (which is destroyed when closed), the side panel's state persists as long as the panel stays open. If the user navigates away and returns, the panel is still there.

However, the panel is per-window, not per-tab. Opening a new window creates a fresh panel instance. Each window gets its own panel, and they don't share JavaScript state — only storage-mediated state.

Communicating with the Panel

The side panel uses the same messaging patterns as any other extension page. NeuralTab's sidepanel.js uses the storage pub/sub pattern (Pattern 4 from Module 06): it listens to chrome.storage.onChanged for networkEvents changes written by the background SW, and updates the live navigation feed without any direct messaging.

// sidepanel.js — reactive to storage changes
chrome.storage.onChanged.addListener((changes, area) => {
  if (area !== 'local' || !changes.networkEvents) return;
  const events = changes.networkEvents.newValue || [];
  const latest = events[events.length - 1];
  if (latest?.type === 'completed') {
    addNavEvent(latest.url);
  }
});

Panel vs. Popup: When to Use Which

Use popup when: the interaction is short (<10 seconds), no state needs to persist between clicks, the feature is "trigger and done" (open a page, copy something, change a setting).

Use side panel when: you need to observe browsing behavior, show real-time updates, maintain conversational state, or display content that users want to reference while reading a page (reading mode, research notes, price comparisons).

Requires Chrome 114+

The sidePanel API requires Chrome 114 or later. Always guard calls with if (chrome.sidePanel) to avoid errors on older Chrome versions. The Module 17 NTCompat.hasSidePanel() helper provides this guard throughout the extension.

Exercises

Exercise 16-A — Open the Panel

Install Module 16's extension. Click the NeuralTab icon — the side panel should open instead of a popup (because setPanelBehavior was called in onInstalled). Navigate several pages. Confirm the live navigation feed updates in real time. Count the navigation events in the feed and compare to the network events in storage.

Exercise 16-B — Panel Toggle

Modify background.js to toggle between panel and popup behavior: if the panel is already open, the extension icon should close the panel and re-enable the popup. Store the current mode in chrome.storage.session. This requires listening to chrome.action.onClicked — which means removing default_popup from manifest.json.

Exercise 16-C — Domain Highlights

Extend sidepanel.js to count how many times each domain appears in the navigation feed. Display the top 5 most-visited domains during the current session as a small leaderboard in the panel. Update it every time a new navigation event arrives via storage.onChanged.
