Module 17 — Cross-Browser Compatibility

NeuralTab Curriculum · Module 17 of 25

Two Namespaces, One Protocol

Firefox was the first browser to implement WebExtensions — the MV2 extension standard. Firefox used a browser.* namespace with Promise-based APIs. Chrome implemented the same APIs under chrome.* with callback-based APIs. They're functionally equivalent — same method names, same parameters — but the interface style differs. Safari added its own implementation in Safari 14, mostly following Firefox's Promise style.

The practical consequence: code written for Chrome (chrome.tabs.query(opts, callback)) doesn't run in Firefox without changes. The solution is a polyfill that wraps Chrome's callback APIs in Promises and exposes them as browser.*.

The Promisify Pattern

function promisify(fn, context) {
  return function(...args) {
    return new Promise((resolve, reject) => {
      fn.call(context, ...args, (result) => {
        if (chrome.runtime.lastError) {
          reject(new Error(chrome.runtime.lastError.message));
        } else {
          resolve(result);
        }
      });
    });
  };
}

The polyfill wraps entire namespaces at once. wrapNamespace(chrome.tabs) returns an object where every method is a promisified version. This is assigned to window.browser.tabs, giving you await browser.tabs.query(...) in Chrome.

NTCompat — Feature Detection

Polyfilling the namespace is not enough. Even with browser.* available everywhere, Chrome-specific APIs like sidePanel don't exist in Firefox. Use feature detection before calling these APIs:

// NTCompat from browser_polyfill.js
const NTCompat = {
  hasSidePanel:  () => typeof chrome.sidePanel !== 'undefined',
  hasSession:    () => typeof chrome.storage?.session !== 'undefined',
  hasOffscreen:  () => typeof chrome.offscreen !== 'undefined',
  isFirefox:     () => navigator.userAgent.includes('Firefox'),
  isChrome:      () => !!window.chrome && !NTCompat.isFirefox(),
  manifestVersion: () => chrome.runtime.getManifest().manifest_version,
};

// Usage in background.js:
if (NTCompat.hasSidePanel()) {
  chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
}
Firefox MV3 Note

Firefox adopted MV3 in Firefox 109 but with differences: Firefox's service worker model allows importScripts from extension files (Chrome doesn't in module SW), and Firefox doesn't enforce some MV3 CSP restrictions as strictly as Chrome. Test on both engines if targeting cross-browser deployment.

Exercises

Exercise 17-A — Test the Polyfill

Open the compat.html page in NeuralTab. Read the "Current Environment" card — it should show your Chrome version, whether sidePanel is available, whether session storage is available, and the manifest version. Then try opening compat.html in Firefox (after loading the extension there) and compare the capability differences shown in the environment card.

Exercise 17-B — Conditional sidePanel

Modify popup.js to show a "Open Side Panel" button only when NTCompat.hasSidePanel() returns true. In browsers without sidePanel support, show an "Open Dashboard" button that opens popup.html in a tab instead. This gives Firefox users a comparable experience without throwing API errors.

Exercise 17-C — Promise vs Callback

Without the polyfill, write chrome.tabs.query in callback style and in Promise style (using the native Promise that Chrome 99+ returns). Then write the same call using the browser.* polyfill. Compare readability. Identify one scenario where the native Chrome Promise API and the browser.* polyfill behave differently (hint: error handling in older Chrome versions).
