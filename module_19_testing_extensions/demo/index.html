Module 19 — Testing Chrome Extensions

Jest for unit logic, Playwright for E2E with a real Chrome instance. Two layers, two purposes.

The Testing Pyramid for Extensions

        E2E (Playwright)        ← few, slow, real Chrome
       ─────────────────────
      Integration (jest + mock) ← moderate, fast
     ─────────────────────────────
    Unit (jest, pure functions)   ← many, instant

Running the Tests

npm install
npm test                    # Jest unit tests
npm test -- --coverage      # with coverage report
npm run test:e2e            # Playwright (requires Chrome)

The Chrome Mock Pattern

// In each test file:
global.chrome = {
  storage: {
    local: {
      get: jest.fn((keys, cb) => cb({ ...mockStore })),
      set: jest.fn((data, cb) => { Object.assign(mockStore, data); cb(); }),
      getBytesInUse: jest.fn((_, cb) => cb(42)),
    }
  },
  runtime: { lastError: null }
};

What to Test vs. What Not to Test

Test: version comparison logic, migration runner filtering, storage key handling, analytics bucketing, license validation caching logic.

Don't test: the actual chrome.storage API behavior (that's Chrome's code), the DOM rendering of popup.html (that's Playwright's job), or timing-dependent service worker lifecycle events.
