🔬 Extension Autopsy I

Deep dissection of two famous commercial extensions: Honey (PayPal) and Grammarly. What permissions do they request? What data do they collect? Are they doing anything malicious — or just privacy-invasive by design?

🍯 Honey
~17 million users · Acquired by PayPal for $4B in 2020

Permissions Requested

<all_urls> tabs webRequest storage cookies (shopping domains)

What It Actually Does

Honey injects content scripts on every page to detect checkout forms and coupon fields. It intercepts navigations to affiliate link targets and replaces the referring affiliate ID with Honey's own affiliate ID — even when the user arrived via a creator's affiliate link. This was exposed in the 2024 MegaLag investigation.

// Honey's affiliate hijacking pattern (reconstructed) // When user clicks creator's affiliate link: // https://shop.example.com?ref=creator123 // Honey intercepts and redirects to: // https://shop.example.com?ref=honey_affiliate // PayPal earns the commission. Creator earns nothing.

⚠ Verdict: Legally compliant but ethically problematic. The affiliate hijacking is disclosed in ToS (page 47 of 52). Users don't know. Creators lose revenue silently.
📝 Grammarly
~10 million users · $13B valuation · Used in enterprise

Permissions Requested

<all_urls> storage identity contextMenus

What It Actually Does

Grammarly injects a content script on every page that reads text from all input fields, textareas, and contenteditable elements. This text is sent to Grammarly's servers for grammar and spell checking. By necessity, this includes every email, password field (if auto-fill isn't used), private message, document, and form field on every website.

// Grammarly's text extraction pattern (reconstructed) document.addEventListener('input', e => { const el = e.target; if (el.matches('input, textarea, [contenteditable]')) { sendToGrammarlyAPI(el.value || el.textContent); } }, true); // This fires on EVERY keypress on EVERY website.

Why This Is a Security Risk

Security researchers at Tavis Ormandy (Google Project Zero) and others have flagged Grammarly for sending auth tokens in ways that allowed cross-site access. The core issue: an extension reading all text input on all pages is a high-value target. A single supply chain compromise of Grammarly would expose the typed content of millions of users across every website they visit.

⚠ Verdict: Legitimate product, significant attack surface. Grammarly must be excluded from security-sensitive pages (banking, HR, legal) at the enterprise level. Their privacy policy is transparent but the surface area is enormous.
