Anatomy of a Real Extension

Reading other extensions' source code is the fastest way to understand what's actually possible — and what's common practice vs. what you should never do. Chrome extensions are distributed as ZIP files of plain JavaScript. Any extension installed in your browser can be found at %LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions\<id>\ and read directly. This module autopsies two extensions with hundreds of millions of users.

Honey: Affiliate Replacement

Honey's stated purpose is finding coupon codes. Its actual business model is affiliate marketing: when you're about to buy something, Honey replaces the merchant's existing affiliate referral code with its own PayPal-owned code — earning Honey a commission on the sale that would have gone to the content creator or site that referred you.

How it works technically:

  • Content scripts with matches: ["<all_urls>"] inject on every page.
  • The script reads cookies with names matching known affiliate patterns (tag=, ref=, aff_id=).
  • When a checkout page is detected (URL patterns like /checkout, /cart), Honey's affiliate code is injected into the URL or form fields.
  • The merchant's analytics shows the sale attributed to Honey, not the original referrer.

This behavior was disclosed in Honey's privacy policy in fine print, but the FTC investigation (2024) concluded the disclosure was insufficient given the deceptive framing of the product as a user-benefit tool.

Grammarly: Surface Area of Trust

Grammarly is a legitimate and widely-used writing assistant. It captures every keystroke in text inputs — which is exactly what it needs to do to check grammar. The concern isn't malice; it's surface area.

// The content script attaches to every editable element:
document.addEventListener('focusin', (e) => {
  if (isEditable(e.target)) {
    e.target.addEventListener('input', captureText);
    e.target.addEventListener('keydown', captureKeydown);
  }
}, true);

With matches: ["<all_urls>"], Grammarly captures text in: banking login forms (before the password field is identified as type="password"), internal company tools, medical record systems, lawyer-client communications, and mental health journaling apps. The extension correctly filters type="password" fields — but a bug or deliberate change could remove that filter. 35 million users would immediately be affected.

The Lesson: Permission Surface Area

Both extensions request <all_urls> host permission — which is necessary for their core features. This is a design constraint, not a flaw. The lesson for your own extensions: be as specific as possible. If your coupon finder only works on Amazon, match *://*.amazon.com/*. If your writing assistant only improves emails, match *://mail.google.com/*. Every URL you don't match is a user who doesn't have to trust you.

How to Read an Extension's Source

Install the extension. Open chrome://extensions → find the extension → click "Details" → note the Extension ID. Navigate to %LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions\<ID>. The latest version folder contains all the files. Use VS Code to read them. Start with manifest.json to understand all declared permissions and entry points, then follow the content scripts and background to understand actual behavior.
