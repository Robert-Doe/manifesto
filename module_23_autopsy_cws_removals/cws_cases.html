📋 Autopsy III — CWS Policy Removals

Real cases of Chrome Web Store extensions being removed or force-disabled. Each case study identifies the policy violation, what tipped Google off, and what legitimate developers should learn from it.

The Great Suspender
Removed: Feb 2021
~2 million users · Tab suspension extension
MALWARE

The extension was sold to an unknown buyer in 2020. The new owner pushed an update that added tracking code and injected JavaScript from remote servers. The original open-source maintainer was unaware. Chrome force-disabled all installations with a security warning, which was unprecedented at the time.

What tipped Google off: The new version made network requests to domains that security researchers flagged. The extension began injecting remote scripts (violation of MV2 CSP that was being enforced). Users reported behavioral changes.

✓ Lesson: Vet extension ownership changes. Before installing an "acquired" extension, check the git history. MV3's CSP prevents remote script injection — a direct response to this class of attack.
DataSpii — The Nacho Analytics Incident
Removed: 2019
~4 million users across 8 extensions
DATA HARVESTING

Security researcher Sam Jadali discovered that a family of 8 browser extensions (including Hover Zoom+, SpeakIt!, SuperZoom) were harvesting full browsing history including URLs with sensitive tokens in them — password reset links, Dropbox document links, airline booking confirmations. This data was being sold to a company called Nacho Analytics that repackaged it as "business intelligence."

What tipped Google off: Jadali's report included specific evidence of the data pipeline. The extensions used <all_urls> access to log every URL visited, including URLs containing authentication tokens.

✓ Lesson: Browsing history + <all_urls> is a high-risk combination. NeuralTab stores history in IndexedDB locally with no exfiltration. If you build a history feature, make this explicit in your privacy policy.
Stylish — 1.8M Users, All Browsing History Sold
Removed: Jul 2018
~1.8 million users · CSS theming extension
DATA HARVESTING

Stylish (a legitimate, beloved extension for applying custom CSS to websites) was acquired and the new owners added code to collect the full browsing history of all users and sell it. The extension sent every URL visited, along with a unique user ID, to their servers. Robert Heaton's investigation showed the data pipeline in detail.

Technical implementation: A single added line called a tracking function on every page load in the content script. The function POSTed the current URL and a cookie-derived user identifier to their analytics endpoint.

✓ Lesson: Content script + history tracking = severe privacy violation. Google's response: new CWS policy requiring explicit disclosure of data collection. Privacy practices are now a required field in the CWS developer dashboard.
Session Replay Extensions (2023 batch removal)
Removed: 2023
~200,000 users across multiple extensions
POLICY VIOLATION

A batch of extensions claimed to provide "productivity tools" but were recording full session replays (keystrokes, mouse movements, form inputs) on all websites using the same technology as FullStory and Hotjar — but without user consent and transmitting data to third-party servers. Violated the User Data Privacy policy section on keystroke logging.

✓ Lesson: Session replay = automatic removal. Any extension that records keystrokes or input content and sends it off-device violates CWS policy regardless of stated purpose.

CWS Policy Landmines — What Gets Extensions Killed

Automatic Removal Triggers
  • Remote code execution — eval, remote scripts
  • Keystroke logging — recording input fields
  • Selling browsing data — any commercialization
  • Hidden functionality — behavior not in description
  • Obfuscated code — minification ok, obfuscation not
  • Deceptive install — misleading screenshots/description
Warning / Manual Review Triggers
  • Excessive permissions — unused permissions
  • Undisclosed data collection — must be in privacy policy
  • <all_urls> without justification — must explain why
  • Native messaging — requires justification
  • Debugger permission — requires clear use case
  • Rapid version updates — triggers re-review
