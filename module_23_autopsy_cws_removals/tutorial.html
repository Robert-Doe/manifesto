Four Removals Worth Studying

The Chrome Web Store has forcibly removed extensions millions of times. Most removals are low-profile: a single spam extension, quickly gone. But a handful of high-profile cases shaped the policies that govern the store today. Each is a lesson in what Google considers a line — and how close legitimate extensions can get to that line before crossing it.

The Great Suspender — February 2021
2 million users · Force-disabled across all Chrome installations

The Great Suspender was a legitimate tab-suspension extension with an open-source codebase and millions of users. The original developer sold it to an anonymous buyer in 2020. The new owner added obfuscated tracking code and a remote code execution mechanism — loading JavaScript from an external server — which allowed arbitrary code to run in the extension context. Google force-disabled the extension across all Chrome installations simultaneously, which users experienced as their suspended tabs disappearing and the extension icon vanishing. The lesson: supply chain. Acquiring an extension to exploit its user base is a recognized attack pattern. If you buy or sell an extension, both parties need to disclose the change to users.

DataSpii — July 2019
7 extensions · ~4 million users · Leaked browsing history to data brokers

DataSpii was discovered by security researcher Sam Jadali. Seven extensions quietly collected users' complete browsing history — including URLs that contained confidential information like documents and private GitHub links — and sent it to a data broker that resold it as "anonymous" analytics. The extensions had legitimate stated purposes (coupons, tab management). The collection happened via content scripts that read window.location.href on every page, attached to a load event listener, and sent batches to an analytics server every few minutes. The lesson: collecting data you don't disclose is grounds for removal, even if the data appears innocuous and you never sell it by name.

Stylish — July 2018
2 million users · Collected full browsing history with timestamps

Stylish was one of the most popular extensions for custom website styling. After being acquired by SimilarWeb in 2017, Stylish's update added a new feature: it sent every URL the user visited — including search queries — to SimilarWeb's analytics servers. This was disclosed in the updated privacy policy, but not prominently. Mozilla removed it first; Google followed within 24 hours. The case established that disclosed-but-obscured data collection is treated the same as undisclosed collection by both stores. The lesson: privacy policy disclosure must be prominent, not buried in a legal document no user reads.

Session Replay Batch — 2023
~40 extensions · Used content scripts to capture form inputs and session data

A coordinated batch of extensions — all with innocuous names like "PDF Converter" and "Screen Capture" — were found to inject session replay scripts that recorded user interactions (mouse movements, clicks, form values) and sent them to remote servers. The extensions used a common technique: loading the replay SDK dynamically from a CDN after passing review (the delayed payload pattern from Module 22). MV3's remote code blocking would have prevented this specific vector. The lesson: MV3's blocking of remote scripts is a genuine security improvement, not just a restriction on developers.

The Common Thread

Every removal shares a root cause: the extension collected or transmitted data that users didn't know about and didn't consent to, or executed code that wasn't in the reviewed package. MV3's structural changes prevent the code-execution vector. But data collection — reading the DOM, reading URLs, reading cookies — is still fully possible in MV3. The defense is transparency and minimal collection, not technical restriction.

Automatic Removal Triggers

Google can (and does) force-disable extensions remotely without the developer's involvement. This power exists specifically to respond to cases like The Great Suspender — where millions of users are at risk and waiting for a developer to push an update is too slow. Build your extension assuming Google can pull the plug at any time, and structure your data storage so users aren't harmed if that happens suddenly.
