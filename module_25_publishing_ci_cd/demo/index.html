Module 25 — Publishing & CI/CD

From git push to Chrome Web Store in one pipeline. The final module — ship it.

The Pipeline

Lint & Validate
manifest.json check, Jest unit tests, coverage gate
→
Build & Package
Vite build, zip with exclusions, version tagging
→
Publish to CWS
items.upload + items.publish via CWS API (main only)

Required GitHub Secrets

CWS_EXTENSION_ID    # Your extension's ID from CWS dashboard
CWS_ACCESS_TOKEN    # OAuth2 access token for CWS API
CODECOV_TOKEN       # (optional) coverage reporting

Getting the CWS Access Token

# 1. Create project in Google Cloud Console
# 2. Enable Chrome Web Store API
# 3. Create OAuth2 client credentials (Desktop app type)
# 4. Exchange for refresh token via OAuth2 playground
# 5. In CI: exchange refresh token for access token:
curl -X POST https://oauth2.googleapis.com/token \
  -d "client_id=CLIENT_ID" \
  -d "client_secret=CLIENT_SECRET" \
  -d "refresh_token=REFRESH_TOKEN" \
  -d "grant_type=refresh_token"

Review Time Expectations

New extension, low permissions: 1-3 days. New extension with debugger/identity/<all_urls>: 1-3 weeks. Update, no new permissions: 1-2 days. Update adding permissions: triggers full re-review. Plan your release schedule around these windows — shipping the Friday before a holiday is a reliable way to spend two weeks waiting.
